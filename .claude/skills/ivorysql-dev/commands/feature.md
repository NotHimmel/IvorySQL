# /ivorysql:feature

Automated end-to-end feature development workflow that generates code templates, builds, tests, commits, pushes, and creates a PR.

## Usage

```bash
# Create PL/iSQL package
/ivorysql:feature --name DBMS_MY_PACKAGE --type plisql-package

# Create SQL function
/ivorysql:feature --name my_distance_function --type sql-function

# Create contrib module
/ivorysql:feature --name my_extension --type contrib-module

# Create regression test
/ivorysql:feature --name interval_tests --type regression-test

# Custom branch name
/ivorysql:feature --name DBMS_UTILITY --type plisql-package --branch-name feat/dbms-utility-hash
```

## Arguments

| Argument | Short | Required | Description |
|----------|-------|----------|-------------|
| `--name` | `-n` | Yes | Feature/module/package/function name |
| `--type` | `-t` | Yes | Feature type |
| `--branch-name` | No | Custom branch name (default: `feat/<name>`) |
| `--no-test` | No | Skip running tests (not recommended) |
| `--draft` | No | Create PR as draft |
| `--description` | `-d` | No | Short description for PR title |

## Feature Types

| Type | Description | Generated Files |
|------|-------------|-----------------|
| `plisql-package` | PL/iSQL package | `.sql`, `.c`, `.h` files |
| `sql-function` | SQL function | `.c` file with SQL function |
| `contrib-module` | Contrib extension | Complete module structure |
| `regression-test` | Regression test | `.sql` and `.out` files |

## Behavior

### 1. Generate Branch Name

Creates branch name from feature type and name:

```bash
# Default format
git checkout -b feat/dbms_my_package

# Or custom
git checkout -b feat/dbms-utility-hash
```

### 2. Generate Code Templates

Creates appropriate files based on feature type:

**PL/iSQL Package:**
```
contrib/ivorysql_ora/src/builtin_packages/dbms_<name>/
  ├── dbms_<name>.sql        -- Package specification
  ├── dbms_<name>.c          -- C implementation
  └── dbms_<name>--1.0.sql    -- Extension script
```

**SQL Function:**
```
contrib/ivorysql_ora/src/builtin_functions/
  ├── <name>.c                 -- Function implementation
```

**Contrib Module:**
```
contrib/<name>/
  ├── <name>.c                 -- Main source
  ├── <name>--1.0.sql           -- Extension script
  ├── <name>.control           -- Control file
  ├── Makefile                 -- Build configuration
  ├── README.md                -- Documentation
  └── sql/                     -- Test files
```

**Regression Test:**
```
src/oracle_test/regress/sql/
  ├── <name>.sql               -- Test input
  └── expected/
      └── <name>.out           -- Expected output
```

### 3. Update Build Files

For new modules, updates:
- `contrib/Makefile` - Adds module to SUBDIRS
- `contrib/<module>/Makefile` - Creates build configuration

### 4. Build and Test

```bash
# Build the project
make -j$(nproc)
make install

# Run tests
make oracle-pg-check

# Or run specific module tests
cd contrib/<module> && make check
```

### 5. Commit

Creates commit with proper format:

```
feat: Add <feature description>

<implementation details>

Co-Authisted-By: Claude <noreply@anthropic.com>
```

### 6. Push and Create PR

```bash
git push -u origin <branch-name>

gh pr create \
  --title "<auto-generated title>" \
  --body "<auto-generated body>" \
  --base master \
  --repo IvorySQL/IvorySQL
```

## Feature Type Details

### PL/iSQL Package

Generates a complete PL/iSQL package with:

**Files created:**
```
contrib/ivorysql_ora/src/builtin_packages/dbms_<name>/
  ├── dbms_<name>.sql        -- Package spec (DECLARE section)
  ├── dbms_<name>.c          -- Package body (BEGIN section)
  └── dbms_<name>--1.0.sql    -- Extension installation
```

**Template includes:**
- Package specification with procedures/functions
- Error handling with RAISE_APPLICATION_ERROR
- Input validation
- Documentation comments
- SQL/MM/dd/YYYY date format for CHANGELOG

**Example:**

```bash
/ivorysql:feature --name DBMS_CRYPTO --type plisql-package
```

Creates:
- Package spec with ENCRYPT, DECRYPT, HASH functions
- C implementation using PostgreSQL crypto APIs
- Extension script for loading

### SQL Function

Generates a SQL function implementation:

**Files created:**
```
contrib/ivorysql_ora/src/builtin_functions/
  └── <name>.c
```

**Template includes:**
- Function declaration (PG_FUNCTION_INFO_V1)
- Input validation and error handling
- Implementation logic
- Documentation comments

**Example:**

```bash
/ivorysql:feature --name calculate_distance --type sql-function
```

Creates function with parameters for coordinate calculation.

### Contrib Module

Generates a complete contrib extension:

**Files created:**
```
contrib/<name>/
  ├── <name>.c                 -- Main source file
  ├── <name>--1.0.sql           -- Extension script
  ├── <name>.control           -- Control file
  ├── Makefile                 -- Build configuration
  ├── README.md                -- User documentation
  └── sql/
      ├── <name>_test.sql      -- Test file
      └── expected/
          └── <name>_test.out  -- Expected output
```

**Template includes:**
- Standard PGXS structure
- Data type definitions
| Function | Description |
|----------|-------------|
| `REGRESS_OPTS` | Test options |
| `EXTENSION` | Extension name |
| `MODULE_big` | Main object file |
| `OBJS` | Object files |
| `DATA` | SQL script files |

**Example:**

```bash
/ivorysql:feature --name my_extension --type contrib-module
```

Creates a new contrib extension with build infrastructure.

### Regression Test

Generates Oracle compatibility test:

**Files created:**
```
src/oracle_test/regress/
  ├── sql/
  │   └── <name>.sql           -- Test SQL
  └── expected/
      └── <name>.out           -- Expected output
```

**Template includes:**
- Setup and cleanup
- Test cases with positive/negative scenarios
- Oracle-specific syntax
- Expected output with comments

**Example:**

```bash
/ivorysql:feature --name interval_stress_test --type regression-test
```

Creates comprehensive interval datatype stress tests.

## Error Handling

### Feature Already Exists

**Action:** Stops workflow and asks for confirmation

**Options:**
- Modify existing feature
- Use different name
- Cancel

### Build Fails

**Action:** Shows build errors

**Recovery:** Fix issues and retry

### Tests Fail

**Action:** Shows test failures

**Options:**
- Continue anyway
- Stop to fix tests
- Create draft PR

## Code Generation Templates

### PL/iSQL Package Template

Generates:

1. **Package specification** (`dbms_<name>.sql`):
   - DECLARE section with procedures/functions
   - Parameters with types
   - RETURN types

2. **Package body** (`dbms_<name>.c`):
   - Function implementations
   - Error handling
   - Input validation
   - Memory management with palloc/pfree

3. **Extension script** (`dbms_<name>--1.0.sql`):
   - CREATE EXTENSION command
   - GRANT EXECUTE permissions
   - Version comment

### SQL Function Template

Generates:

1. **Function implementation**:
   - PG_FUNCTION_INFO_V1 declaration
   - PG_GETARG_XXX for parameters
   - ereport for errors
   - PG_RETURN_XXX for return value

## Post-Creation Steps
