# /ivorysql:fix-bug

Automated end-to-end bug fix workflow that reads a bug report, fixes the code, runs tests, commits, pushes, and creates a PR.

## Usage

```bash
# Fix bug by ID (reads bug-fix-<id>.md)
/ivorysql:fix-bug --bug-id 06

# Fix with custom branch name
/ivorysql:fix-bug --bug-id 06 --branch-name hotfix/sprintf-overflow
```

## Arguments

| Argument | Required | Description |
|----------|----------|-------------|
| `--bug-id` | Yes | Bug ID (reads `bug-fix-<id>.md`) |
| `--branch-name` | No | Custom branch name (default: `fix/<bug-description>`) |
| `--no-test` | No | Skip running tests (not recommended) |
| `--draft` | No | Create PR as draft |

## Behavior

### 1. Read Bug Report

Reads `bug-fix-<bug-id>.md` from the project root to understand:
- Bug description and location
- Files and line numbers affected
- Suggested fix approach

Example bug report format:

```markdown
**Title:**
  [BUG] Buffer overflow in dsinterval.c

**Description:**
  Multiple sprintf() calls without bounds checking

**Location:**
  - File: `contrib/ivorysql_ora/src/datatype/dsinterval.c`
    - Lines: 709, 711, 715, 722, 724, 791, 807, 816, 820, 826

**Problem:**
  sprintf(cp, "%0*d %02d:%02d:", day_precision, mday, hour, min);

**Suggested Fix:**
  snprintf(cp, bufsize, "%0*d %02d:%02d:", day_precision, mday, hour, min);
```

### 2. Create Branch

Generates branch name from bug title or uses `--branch-name`:

```bash
# Default format
git checkout -b fix/sprintf-buffer-overflow

# Or custom
git checkout -b hotfix/sprintf-overflow
```

### 3. Apply Fix

Automatically applies code changes:
- Reads affected files
- Replaces sprintf with snprintf
- Adds buffer size parameters
- Updates function signatures

### 4. Build and Test

```bash
# Build the project
make -j$(nproc)
make install

# Run Oracle compatibility tests
make oracle-pg-check

# Or run all tests if preferred
make check-world
```

### 5. Commit

Creates commit with proper format:

```
fix: Replace sprintf with snprintf in <files>

This fixes buffer overflow vulnerabilities in <affected modules>.

<details from bug report>

Co-Authored-By: Claude <noreply@anthropic.com>
```

### 6. Push and Create PR

```bash
# Push to remote
git push -u origin <branch-name>

# Create PR
gh pr create \
  --title "<auto-generated title>" \
  --body "<auto-generated body>" \
  --base master \
  --repo IvorySQL/IvorySQL
```

## PR Template

Auto-generated PR body:

```markdown
## Summary
Fix buffer overflow vulnerability in <affected modules>

## Bug Report
Resolves issues described in bug-fix-<id>.md:
- <bug-description>

## Changes
- <list of code changes>

## Testing
- [x] Oracle compatibility tests pass (228/228)
- [ ] Manual testing performed
- [ ] Code follows PostgreSQL coding conventions

## Affected Files
- <list of modified files>

## Risk Assessment
- Severity: <from bug report>
- Impact: <from bug report>
- Fix: Replaced sprintf() with snprintf() with proper bounds checking
```

## Pre-flight Checks

Before starting, verifies:

1. **Bug report exists**
   ```bash
   test -f bug-fix-<bug-id>.md
   ```

2. **Working directory is clean**
   ```bash
   git status --porcelain
   ```

3. **No uncommitted changes**
   Prompts to stash or commit if changes detected

4. **Build system ready**
   - Checks for `configure` script or existing build
   - Verifies dependencies

## Error Handling

### Bug Report Not Found

```
Error: bug-fix-<bug-id>.md not found
```

**Solution:** Ensure bug report exists in project root with format:
- `bug-fix-01.md`
- `bug-fix-06.md`
- etc.

### Build Fails

**Action:** Stops workflow and shows build errors

**Recovery:** Fix build issues and retry

### Tests Fail

**Action:** Shows test failures and asks for confirmation

**Options:**
- Continue anyway (creates PR despite test failures)
- Stop to fix tests
- Create draft PR for review

### Git Push Fails

**Action:** Shows error and provides instructions

**Common issues:**
- Authentication required
- Remote doesn't exist
- Network issues

{

```

```

## Branch Naming Conventions

Default branch names follow these patterns:

| Bug Type | Branch Pattern | Example |
|----------|---------------|---------|
| Security | `security/<cve-id>` | `security/cve-2025-001` |
| Hotfix | `hotfix/<description>` | `hotfix/sprintf-overflow` |
| Regular fix | `fix/<description>` | `fix/buffer-overflow` |
| Experimental | `wip/<description>` | `wip/interval-fix` |

## Exit Conditions

**Success:**
- Bug fixed
- Tests pass
- Committed
- Pushed
- PR created
- PR URL returned

**Failure:**
- Bug report not found
- Build fails
- Tests fail (unless `--no-test` or user confirms)
- Push fails
- PR creation fails
- User cancels

## Troubleshooting

### "Bug report not found"

Ensure the bug report file exists:
```bash
ls -la bug-fix-*.md
```

Or create it from template:
```markdown
**Title:**
  [BUG] <short description>

**Description:**
  <detailed description>

**Location:**
  - File: `path/to/file.c`
    - Lines: 123, 456

**Problem:**
  <code example showing the bug>

**Suggested Fix:**
  <code example showing the fix>

**Severity:**
  Critical/High/Medium/Low
```

### "Tests fail but I want to continue"

Use `--no-test` to skip testing, or confirm to continue anyway when prompted.

### "Push fails - authentication required"

```bash
# Authenticate with GitHub
gh auth login

# Or set up SSH key
git remote set-url origin git@github.com:IvorySQL/IvorySQL.git
```

## Notes

- Always review changes before PR is created
- Draft PRs are recommended for complex fixes
- Tests run in Oracle compatibility mode (`-m oracle`)
- The workflow can be interrupted at any step with Ctrl+C
