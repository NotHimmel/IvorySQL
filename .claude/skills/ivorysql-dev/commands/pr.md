# /ivorysql:pr

Create a pull request to the IvorySQL upstream repository using the GitHub CLI.

## Usage

```bash
# Create PR from current branch
/ivorysql:pr

# Custom title and body
/ivorysql:pr --title "fix: Buffer overflow in dsinterval.c"

# Create as draft PR
/ivorysql:pr --draft

# Interactive mode (prompts for details)
/ivorysql:pr --interactive
```

## Arguments

| Argument | Short | Required | Description |
|----------|-------|----------|-------------|
| `--title` | `-t` | No | PR title (default: auto-generated from latest commit) |
| `--body` | `-b` | No | PR body (default: auto-generated from branch/commits) |
| `--draft` | `-d` | No | Create as draft PR |
| `--interactive` | `-i` | No | Interactive mode with prompts |

## Prerequisites

Before creating a PR, this command verifies:

1. **GitHub CLI installed**
   ```bash
   gh --version
   ```

2. **Authenticated with GitHub**
   ```bash
   gh auth status
   ```

3. **Branch is pushed**
   ```bash
   git log origin/$(git branch --show-current)..HEAD
   ```

4. **Tests pass** (optional, configurable)
   - Runs `make check` or `make oracle-check` if configured

5. **Branch name follows convention**
   - `feat/*` for new features
   - `fix/*` for bug fixes
   - `refactor/*` for refactoring

## Behavior

### 1. Verify Environment

```bash
# Check gh CLI
gh --version

# Check auth status
gh auth status

# Check remote
git remote -v | grep upstream
```

### 2. Verify Branch

```bash
# Check current branch
git branch --show-current

# Check if pushed
git log origin/$(git branch --show-current)..HEAD

# If not pushed, push first
git push -u origin $(git branch --show-current)
```

### 3. Generate PR Content

**Auto-generated title:**
```bash
# From latest commit message
git log -1 --pretty=%s
# Example: "fix: Handle NULL in array indexing"
```

**Auto-generated body:**
```bash
# From commits since branching from upstream/master
git log upstream/master..HEAD --pretty=format:"- %s"

# Plus checklist template
```

### 4. Create PR

```bash
gh pr create \
  --title "<title>" \
  --body "<body>" \
  --base upstream/master \
  --repo IvorySQL/IvorySQL
```

## PR Template

The generated PR body includes:

```markdown
## Summary
<auto-generated summary from commits>

## Changes
<list of commits with descriptions>

## Testing
- [ ] PostgreSQL compatibility tests pass
- [ ] Oracle compatibility tests pass
- [ ] Manual testing performed

## Checklist
- [ ] Code follows PostgreSQL coding conventions
- [ ] Tests added for new functionality
- [ ] Documentation updated
- [ ] No AI attribution in commit messages

## Related Issues
Closes #<issue-number>
```

## Interactive Mode

```bash
/ivorysql:pr --interactive
```

Prompts for:
1. PR title (with auto-filled default)
2. Related issue number (optional)
3. Testing status (checklist)
4. Additional notes
5. Draft or ready for review

## Configuration

Uses settings from `.claude/ivorysql-dev.local.md`:

```json
{
  "upstream_remote": "upstream",
  "upstream_owner": "IvorySQL",
  "upstream_repo": "IvorySQL",
  "default_base": "upstream/master",
  "require_tests": true,
  "auto_push": true
}
```

## Pre-creation Checks

Before creating PR, the command:

1. **Verifies tests pass** (if `require_tests: true`)
   ```bash
   docker compose exec dev make check
   docker compose exec dev make oracle-check
   ```

2. **Checks commit messages**
   - No AI attribution
   - Follows commit spec
   - Proper type prefix

3. **Verifies branch naming**
   - `feat/*`, `fix/*`, `refactor/*`, etc.

4. **Checks for merge conflicts**
   ```bash
   git fetch upstream
   git merge-base upstream/master HEAD
   ```

## Exit Conditions

**Success:**
- PR created
- PR URL returned

**Failure:**
- gh CLI not installed/authenticated
- Tests failing (if configured to check)
- Branch not pushed
- Merge conflicts detected

**User cancel:**
- Aborted before creation

## Error Recovery

### Branch Not Pushed

```bash
# Automatically pushes
git push -u origin $(git branch --show-current)
```

### Merge Conflicts

```bash
# Suggests rebasing
git fetch upstream
git rebase upstream/master

# Then push force
git push --force-with-lease
```

### gh CLI Not Authenticated

```bash
# Provides instructions
gh auth login
```

## Notes

- PRs should target `upstream/master`, not your fork's master
- Always ensure tests pass before creating PR
- Use draft PRs for work-in-progress
- Reference related issues with "Closes #<number>"
